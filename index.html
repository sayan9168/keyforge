        SMALL HABITS. STRONGER SECURITY.

        A better set of defaults.

        Good passwords are only one part of staying protected.

        01 /

        One account. One password.

        Reuse turns one breach into many. Let a reputable password manager generate and remember a different password for every account.

        02 /

        Memorable, not predictable.

        Choose independently random words, not a quotation or personal story. Start with six words from the EFF long list. Never reuse a public example.

        03 /

        Go beyond a password.

        Use passkeys or a security key when offered. Otherwise enable an authenticator app, and keep recovery codes somewhere safe.

        04 /

        Complexity isn’t randomness.

        “Password” with a capital, a number, and a symbol is still predictable. Length helps most when it comes from genuinely random choices.

        05 /

        No match doesn’t mean safe.

        Breach datasets are incomplete. If a password has been exposed, replace it everywhere it was used and review active account sessions.

        06 /

        Mind what you leave behind.

        Clipboard managers and exported files may retain secrets. Clear session only clears this page—not your clipboard, downloads, or browser extensions.

        How does KeyForge estimate strength?

        The checker uses the local zxcvbn-ts engine with common-password and English dictionaries. It looks for likely guessing strategies, including repetitions, keyboard walks, dates, and substitutions. The 0–4 rating and guess counts are estimates, not guarantees. Other languages and personal context may be modeled poorly.

        Human-chosen text has no directly measurable entropy. Only the generator shows generation entropy, calculated from its known, uniformly sampled output space. Literal characters and deterministic capitalization add none.

        Guess times use your selected illustrative attack rate. Actual resistance depends on password hashing, hardware, rate limits, and what an attacker knows. Nothing here is labeled “uncrackable” or “quantum-safe.”

        What happens to my passwords?

        Generation, analysis, comparison, and optional history run in page memory. No passwords are written to browser storage, sent to analytics, or included in URLs. Fonts, dictionaries, and application code are hosted with the app.

        The only external API request is a breach lookup you explicitly allow and click. It sends a five-character hash prefix to Have I Been Pwned, without cookies, caching, or a referrer. This reduces disclosure but is not anonymity: the service sees your IP and the prefix.

        Revealed passwords are hidden when the tab goes into the background. Clear session drops page references and resets the interface, but JavaScript cannot guarantee forensic memory erasure. This is a tool, not a password vault.
